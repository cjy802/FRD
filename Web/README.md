# 低空飞行决策工作台 · 第一版

本项目包含 Vue 3 + Vite + TypeScript 页面、Cesium 地图和 FastAPI 接口。后端用江苏 OSM 本地索引（缺少索引时用校园快照）计算道路参考路线；自动取当前公开 GFS 起报资料并运行 FuXi，按航线坐标、逐点 ETA 和 AGL 高度风进行有限变量的气象初筛。页面已接入动态决策、候选出发时次和道路天气比较。机型手册、空域、三维障碍、现场起降条件及未覆盖天气因素仍须另行核验，**系统不提供放飞许可**。逐项记录见 [WEATHER_ROADMAP.md](WEATHER_ROADMAP.md)。

## 启动

后端（Python 3.10+；首次使用 PBF 先建立索引）：

```powershell
cd backend
python -m pip install -r requirements.txt
python scripts/index_pbf.py --source ..\..\jiangsu-260916.osm.pbf
python -m uvicorn main:app --reload --host 127.0.0.1 --port 8011
```

前端（Node 20.19+）：

```powershell
cd frontend
npm install
npm run dev
```

前端默认将 `/api` 请求代理到 `http://127.0.0.1:8011`，与上面的后端端口一致。
使用其他端口时，在 `frontend/.env.local` 中设置
`VITE_API_TARGET=http://127.0.0.1:端口` 后重启前端；终端中设置的同名环境变量优先。
开发服务器和 `npm run preview` 使用相同的代理目标。

百度地图 JSAPI Three 的 AK 在 `frontend/.env.local` 配置，空白模板见
`frontend/.env.example`。依赖和静态资源复制已配置；配置或修改 AK 后重启前端，
访问 `http://127.0.0.1:5173/baidu-preview.html`。
当前地图接入评估与后续实现步骤见 [BAIDU_JSAPI_THREE.md](BAIDU_JSAPI_THREE.md)。

航线设置标题下的“搜索地点”支持地点名称和完整门牌地址；默认搜索常州市，可展开城市选项修改范围。搜索结果展示换算为 WGS84 的纬度和经度；点击结果右侧按钮可把地点应用到任意主点，或追加为新主点。输入框内的定位按钮可取得当前位置并识别附近中文地名，再按该地名搜索周边。地址解析模糊时会提示核对位置。

搜索由后端调用百度地点检索 V3、地理编码 V3 或全球逆地理编码 V3。复制 `backend/.env.example` 为 `backend/.env`，填入 `BAIDU_WEB_SERVICE_AK`；也可使用同名环境变量（优先）。需要服务端 AK，并在百度控制台开启相应服务、配置实际后端出口 IP 白名单。后端每次搜索读取配置，修改 AK 无需重新构建前端。密钥不发送给浏览器，`.env` 不纳入 Git。百度返回 240 时表示 AK 对应服务未开启；校验、配额及超时分别显示原因。

左侧主点列表末尾的“＋ 添加主点”会新增一张空白坐标卡。可在卡片填写经纬度、使用当前位置、选择地图点位，或通过地点搜索填入；点击卡片定位按钮后会先列出当前位置附近的建筑/地点，选择候选后才写入该主点并检查起降条件；未设置的点不会发送给路线规划器。第一个主点为起点、最后一个为终点，其余为途经主点。路线依次计算每对相邻主点，自动生成两点之间的折线小点；小点仅在地图上以小圆点标识，不占用主点卡片。可对主点排序或删除，整条路线、累计时间和沿线天气随点位变化重新计算。多段路线暂不进行 A/B 道路候选比较。

地图右上角的无人机按钮可回放已规划的完整路线。按钮旁可选择 0.5×、1×、2×、4×、8× 倍率，并拖动进度条定位到任意位置；暂停后保留当前位置，播放到终点后可重播。地图上的箭头按航向移动，右下角同步展示按节点高度、机头方向和云台俯仰插值的模拟视角。更改路线会清除回放；回放不改动节点参数，也不代表真实无人机视频或飞控仿真。

访问 `http://127.0.0.1:5173`。地图左上方可切换“本地 / 在线”道路参考路线；起点和终点旁的按钮可分别显示或隐藏淡色的 35 米接路搜索范围，开关只改变显示。点击地图选点时，先用本地 OSM 数据检查已收录建筑及范围内道路：建筑点不采纳，离路太远的点立即提示。无建筑记录仅表示可进入下一步核验，**不能据此认定可以降落**。计算期间地图显示毛玻璃加载层，点击叉号会中止浏览器请求并忽略迟到的结果。本地模式使用已建立的 PBF 索引，不在规划时联网；在线模式调用 OSRM 机动车道路路线服务，网络不可用时返回明确错误，不自动改成本地结果。在线路线按机动车行驶时间选择道路，且不检查建筑缓冲，因此两种模式的结果和约束并不相同。在线服务地址可通过 `ONLINE_ROUTER_URL` 改成自己的 OSRM 服务；默认公共演示服务器只适合原型测试，使用时遵守 [OSRM 演示服务政策](https://github.com/Project-OSRM/osrm-backend/wiki/Api-usage-policy)。更换 PBF 后先停止后端，再重新运行索引脚本（Windows 正在使用的数据库文件可能无法替换）。Cesium 脚本和 OpenStreetMap 显示底图仍需网络。`GET /api/health` 的 `road_data` 字段可确认当前本地模式使用 `jiangsu_pbf_index` 还是 `campus_osm`。

## 接口

- `GET /api/health`：服务状态
- `GET /api/places/search?query=地点或详细地址&region=常州市`：返回候选名称、地址、`location.lat/lng`（BD-09）和可用的地址匹配精度；名称检索使用 Place V3，街道门牌使用地理编码 V3，无结果时尝试另一接口。缺少 AK、服务未开启、额度耗尽或网络故障返回明确错误，不生成占位坐标。
- `GET /api/weather/status`：历史单点天气和模型状态、可选预报时间、逐变量使用策略
- `GET /api/weather/forecast`：当前模型订正后的历史预报，含 FuXi 原值、最终使用值、来源和派生风速/风向。可用 `init_time_utc`（带时区）及 `lead_hours` 选择记录，默认最新可用记录；不存在的记录返回 422。
- `GET /api/weather/risk`：同一记录的单点地面风雨提示，不改变航线的未评估状态
- `POST /api/weather/predict`：页面进入时发起区域 FuXi 预测，保留起报场和 +6/12/18/24 小时时次，返回任务 ID 和状态；只共享正在运行的任务，不复用已完成的历史预报。
- `GET /api/weather/predictions/{job_id}`：查询预测进度、输入缺失/过期原因，或最终天气预报。
- `GET /api/weather/predictions/{job_id}/sample?latitude=...&longitude=...`：查询实际坐标的区域地面天气，默认 +6h；可用带时区的 `valid_time_utc` 指定覆盖范围内的时刻。范围外或过期时返回明确错误。
- `POST /api/weather/predictions/{job_id}/route`：请求体包含 `coordinates`（沿路 GeoJSON 坐标 `[经度, 纬度]`）、`departure_time_utc`（带时区）、`speed_kmh`、`altitude_m` 和可选 `profile`（名称与六项自定义限值）。保留路线拐点，并将较长路段细分至不超过 1 km，按累计距离计算各点 ETA。返回地面与高度天气、覆盖不足原因、沿线初筛和分项决策；`flight_permission` 始终为空。
- `POST /api/weather/predictions/{job_id}/windows`：同样的任务参数，比较当前选定出发时间与未来原生时次；任务结束越过资料截止时刻的候选被排除。返回排序依据、完整覆盖数及不能评估的原因；不是连续可飞窗口。
- `POST /api/routes/compare-weather`：包含 `weather_job_id`、起终点、道路来源、缓冲、高度、速度、`departure_time_utc` 和可选 `profile`。生成真实道路备选并比较天气；不能证明有可分辨改善时保留道路基线。不会自动改变当前路线，须显式采用。
- `POST /api/routes/plan`：请求体的 `road_source` 为 `local`（默认）或 `online`。本地模式从索引按 A/B 范围加缓冲提取路网；在线模式向 OSRM 请求完整道路几何。两种模式均输出 GeoJSON 路线、道路名称、道路/直线距离、端点接入距离和未评估标记。端点离所选道路网络超过 35 米时返回 422；在线服务不可用时返回 503。
- `POST /api/routes/plan-mission`：请求体包含有序 `anchors`（每项为唯一 `id`、纬度、经度）及道路来源、速度、高度、建筑缓冲。逐段复用两点规划器，返回完整路线、`anchor_indices` 和每段距离/接路信息；某段失败会指出段号和主点，不用直线补齐。主点规划上限为 1000，完整路线最多 10000 个折线点；DJI 导出另受机型和导出器限制。
- `POST /api/routes/export-kmz`：将当前道路参考几何中的自动折线点抽稀、保留手动主点后，导出 DJI WPML 航点 KMZ 草稿。默认 `fly` 模板面向 DJI RC 2 上的 DJI Fly（Air 3/Air 3S/Mini 4 Pro 通用消费级格式）；`m30`/`m3e` 模板面向 DJI Pilot 2 企业机型。请求可通过 `waypoint_settings` 为每个原始点指定相对高度、机头方向模式/角度和摄像头俯仰角；DJI Fly 航线需要先在遥控器中创建占位航线，再保持 UUID 文件名替换 `Android/data/dji.go.v5/files/waypoint/` 下的 KMZ。文件使用相对起飞点高度，仍需核对机型、动作、高度、返航、空域和现场条件；道路参考线不等于已批准的飞行航线。

- `GET /api/dji/rc2/status`、`GET /api/dji/rc2/targets`：仅本机 Windows 会话可用，分别检查导入组件和读取 RC 2 上现有的 `.kmz` 占位航线。
- `POST /api/dji/rc2/import`、`GET /api/dji/rc2/jobs/{job_id}`：生成 DJI Fly KMZ 并异步写入所选占位航线，轮询返回生成文件、备份路径、传输和回读校验状态；单次只允许一个写入任务。
- `GET /api/photo-analysis/health`：仅本机可用，检查 ONNX 与 YOLO 两种照片分析模型的运行环境、权重和 runner。
- `POST /api/photo-analysis/jobs`（multipart，含可选 `model_id`）、`GET /api/photo-analysis/jobs/{job_id}`、`GET /api/photo-analysis/jobs/{job_id}/files/{name}`：上传无人机照片，选择本地 ABCDWaveNet ONNX 或 YOLOv8n-seg 4090 混训冠军，轮询任务并取回叠图/疑似掩膜/置信度图与逐图统计；单次最多 200 张，同时只跑一个任务。
- `POST /api/landing/check`：用本地索引对候选点做快速初筛，返回 `mapped_building`、`road_nearby` 或 `no_road`，以及 35 米接路半径和最近道路点。`landing_verified` 始终为 `false`。
- `POST /api/routes/preview`：保留原有的两点直线基线接口

### Windows 本机导入 DJI RC 2

页面的 DJI Fly 模板可连接本机 RC 2：先在 DJI Fly 中保存一条占位航线，通过 USB 将已解锁的遥控器连接到同一台 Windows 电脑；在导出区域点击“检测 / 刷新设备”，选择遥控器上已有的 `.kmz` 占位文件，再点击“生成 KMZ 并替换所选占位航线”。页面显示生成、备份、传输、回读校验的任务状态。原“导出 DJI KMZ 草稿”按钮仍可下载文件。M30/M3E 的 Pilot 2 模板继续使用下载文件。

后端必须以当前登录用户的交互式 Windows 会话运行，不能在远程服务器或 Windows 服务会话中操作本机 MTP 设备；导入时应使用不带 `--reload` 的后端进程，避免任务中途因代码变更重启。生成文件保存在 `%LOCALAPPDATA%\LowAltitudeWorkbench\DJI\imports\<任务 ID>\<占位文件名>.kmz`；页面导入的原文件备份保存在 `%LOCALAPPDATA%\LowAltitudeWorkbench\DJI\backups\<任务 ID>\`。单独运行 `tools/rc2_mtp_upload.ps1` 时使用它自己的默认备份目录。新环境需用 `tools/build_silent_mtp_helper.ps1` 构建本机助手（需要 `clang-cl` 和 Windows SDK）；`tools/bin/silent_mtp_replace.exe` 是生成产物，不提交到 Git。导入只接受列表中的现有占位文件；回读 SHA-256 一致才显示写入成功，随后仍需在 DJI Fly 中核对航线是否被识别。当前没有 RC 2 真机测试结果；DJI Fly 的这种文件替换方式不是官方公开的第三方导入接口。

未连接遥控器时可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/tests/test_rc2_mtp_upload.ps1`，用临时目录模拟列表、替换和失败恢复；该测试不会访问 MTP 设备。

### 飞行后照片分析（本机）

航线设置里的“飞行后照片”页可把无人机照片上传到本机，选择 `ABCDWaveNet 本地混合模型` 或 `YOLOv8n-seg 4090 混训冠军`。前者由 `WATER_ANALYSIS_PYTHON`（默认 `D:/anaconda/envs/waterseg/python.exe`）运行 `backend/scripts/run_water_onnx.py`，读取 `WATER_ANALYSIS_MODEL_DIR` 下 `registry.json` 指定的 ONNX 模型；后者由 `WATER_ANALYSIS_YOLO_PYTHON`（默认 `D:/anaconda/envs/yolov8-env/python.exe`，需安装 Ultralytics）运行 `backend/scripts/run_water_yolo.py`，读取 `WATER_ANALYSIS_YOLO_MODEL`（默认 `../../model/output/4090_champions/yoloj_mix4_best.pt`）。当冠军权重和环境存在时，页面默认选中 YOLO 冠军；也可切回本地 ONNX 模型。两者都输出叠图、疑似掩膜、置信度图及逐图疑似占比/斑块数。模型文件继续保存在 `model/` 的忽略目录，不复制进 Web 或提交到 Git。没有可用模型时接口会明确报告“未就绪”。结果文件保存在 `backend/user_data/photo_analysis/<任务 ID>/`，接口只允许下载任务清单内的文件。**YOLO 冠军的 3 张本地种子照片参与过训练，不能用这 3 张证明本地泛化；所有疑似水体都只是人工复核线索**，像素占比不是面积，更不是水深、水位或堤防安全结论。上传与分析只在本机回环地址开放，与其他本机设备接口使用相同的来源校验。

上线模型默认读取 `Web/mode/output_production/corrector_ridge.npz`，它由两份表去重后的全部可用样本拟合（目前 3893 条，包含 2024、2025、2026 年），使用已验证方案的公共 8 特征。在训练点及训练覆盖的原生提前量上，温度、U 风、6 小时降水采用订正结果，V 风和海平面气压严格保留 FuXi 原值；其他坐标/高度/时次遵循下述适用范围限制。派生风速、风向以及单点提示均使用最终值。全量拟合不再留测试集，也不产生新的独立测试指标；此前 `output_year_transfer_2026` 验证结果保留不变。

页面的“天气数据”进入时自动发起预测并轮询进度，只显示最终温度、U/V 风、气压、降水、风速与风向，不显示原值/订正值对照或历史日期选择。起报、有效时刻和生成时刻都以北京时间显示。模型的 +6h 是从起报场时刻计算，不伪装为从页面访问时刻开始的逐小时预报。表格查询实际起终点中点，不代表整条航线；“气象风险”仅提示该位置的地面风雨，阈值不是机型飞行限值。当前订正模型只在 31.5°N、119.5°E 的地面变量及原生 lead 6/12/24 上训练：该位置的原生预报保留选择性订正，其他坐标、起报场、18h 和时间插值结果不擅自套用单点模型，并显示原因。

航线设置新增“出发时刻 · 北京时间”，默认使用当前北京时间（精确到分钟），可自行调整。计算道路路线且天气预测完成后，“沿线时间匹配”自动查询沿线各点的经过时刻；修改出发时间或速度不会重新加载模型或下载起报场。修改任一主点后，需要重新计算对应道路路线，旧路线不会继续用于新点位的天气对齐。瞬时地面变量在相邻 6 小时时次之间线性估计；降水取覆盖任务时刻的完整 6 小时累计区间，单独记录起止时刻，不插值成分钟雨强，也不累计重复的沿线雨量。

当前保留 116–122.5°E、30–35.5°N 的 70 通道区域网格，原生分辨率 0.25°。空间插值不能生成街道尺度信息，时间插值不是逐小时模型预报。每个任务的区域网格保存在后端内存，最多保留 8 个任务；后端重启后需重新预测，已有起报资料仍可使用下载缓存。缺失空间、时间或高度覆盖时明确列出原因，不外推、不替换为其他点位或日期。起报已超过 6 小时的旧任务不能继续用于当前初筛，页面也会撤下过期预报和已经过去的任务时刻结果。

## 高度、初筛和决策边界

进入页面无需提供最新起报文件，保持后端 8011 与前端 5173 运行并刷新即可自动预测。待天气生成、道路计算完成后，沿线初筛、时次和道路比较自动进行；修改出发时间、速度、高度或自定义阈值只查询已有天气，不重新运行 FuXi。采用候选时次或道路需要明确点击按钮，随后重新初筛。修改起终点或道路缓冲后要重新计算路线，旧结果会失效。

`app/prepare_gfs_height.py` 自动取得 [NOAA GFS 原生高度层字段](https://www.nco.ncep.noaa.gov/pmb/products/gfs/gfs.t00z.pgrb2.0p25.anl.shtml)：10/20/30/40/50/80/100 米 AGL 的 U/V 风及地面阵风、能见度。优先用 NOMADS 江苏区域筛选，失败时用 NOAA S3 字节范围取所选字段，不下载整个全球 GRIB。保留起报至未来 24 小时的五个时次，记录源周期与源提前量，并校验时间、单位、网格和缺值。高度等于原生层时直接取该层，层间使用明确标识的线性估计；小于 10 米或大于 100 米不外推。高度风是 GFS 资料，不套用单点地面订正，也不冒称 FuXi 100 米风。辅助资料失败时仍显示真实 FuXi 地面天气，但初筛显示高度资料不足。

阵风和能见度是**地面指标**，不代表任务高度阵风、云中能见度、云底或湍流。天气初筛还没有雷暴、结冰等资料；ETA 按填写速度估算，未模拟风对地速、续航或起降工况的影响。地图着色仅表达这些粗网格变量的沿线初筛结果，不是街道级气象观测或已验证的可飞航线。

默认演示限值：高度风 12、侧风 8、逆风 12、地面阵风 15 m/s；六小时雨量 5 mm；最低地面能见度 3000 m。达到限值比例的 80% 触发关注，达到限值触发较强提示；能见度按相反方向判断。参考分为各项数值/限值的最大比例 × 50、封顶 100，能见度使用限值/数值，**不是事故概率**。缺测不按零风评分。可在“任务概览 → 天气初筛阈值”填写自定义气象阈值，天气计算和阈值语义不变。

页面固定在当前视口内；主点较多时左侧设置区域可独立滚动，地图保持固定，任务概览也独立滚动。较矮窗口将左侧设置分为“主点与坐标 / 飞行参数”，避免控件被截断；手机通过“航线设置 / 航线地图 / 任务概览”切换固定面板。切换面板不会重新挂载或重新启动天气预测。

沿线接口增加 `weather_risk` 与 `decision`：分别记录方向分量、最明显触发位置、逐段提示、覆盖状态和预测/高度/机型/空域/障碍/其他天气核验状态。任何等级的 `flight_permission`、`may_fly` 都为空，即使风雨未触发当前规则也不能解读为允许起飞。

页面聚焦天气信息：底部显示“气象结论”和“查看气象数据状态”，只展示区域预报、沿线地面时空、高度风及已覆盖变量初筛；不显示机型、空域审批、障碍/起降点或其他气象危险的待核验清单。缺测、原生分辨率、预报时效和地面指标适用范围仍明确保留。此调整仅影响展示，后端原始检查和空的许可字段保持兼容，不把天气结果转换为飞行许可。可用 `npm run test:weather-presentation` 验证这一展示边界。

窗口比较先要求全任务完整覆盖，再按初筛等级、参考分和较早出发排序；只比较当前选择与原生时次，不宣称分钟级连续窗口。路线比较的本地备选来自同一路网及建筑缓冲约束下的重叠惩罚；在线备选来自 [OSRM 备选路线接口](https://project-osrm.org/docs/v26.6.1/http)，服务失败不切换数据源。备选须跨不同原生天气网格、天气差异达到演示门槛、参考分改善至少 5 且长度不超过基线 1.8 倍，才显示相对较低初筛分备选。门槛不是已验证的模型误差界或飞行限值，结果也不保证全局最优。相同网格、差异不明显、缺测或没有不同道路备选时保留基线并解释原因。

高度下载缓存位于 `app/prepared/gfs_aux_cache/`，与起报缓存分开；仅校验通过的当前数据可复用，只清理生成器登记且有效时刻超过 48 小时的自身缓存。起报资料实际是分析场还是同有效时刻的短时背景，在“天气数据 → 查看起报资料实际来源周期”中可查看。所有模型、下载数据、数据库和截图保持在 Git 之外。

高度资料保留两路并行下载，但 ecCodes 的完整解码/释放过程使用同一进程锁串行执行，避免本机 Windows 原生库在冷启动并发解析时出现定义解析错误或 `0xC0000005` 访问冲突。高度子进程开启故障堆栈，失败提示记录退出码与有限长度的标准错误，不再把所有异常都折叠为“未返回有效数据”。源字段、时间、网格、单位和缺值检查仍保留，失败时不生成占位天气或套用 10 米风。

实时推理默认由程序自动获取 [NOAA 公开 GFS](https://www.nco.ncep.noaa.gov/pmb/products/gfs/nomads/) 的当前气象场，不要求用户提供起报文件。每次进入页面发起预测：自动获取两帧相隔 6 小时的当前资料 → 转成 FuXi 70 通道输入 → 同一 GPU 会话滚动推理 +6/12/18/24h → 保留区域网格并查询实际坐标 → 仅在订正适用点位/时次使用全量模型 → 显示最终值。FuXi 官方也提供了 [GFS 输入转换示例](https://github.com/tpys/FuXi/blob/main/make_gfs_input.py)。本项目保持真实的 6 小时累计降水，不使用示例中的零值占位；位势高度乘标准重力转为位势，温度/湿度/风/气压保留对应物理单位。

自动获取脚本为 `app/prepare_gfs_live.py`，通过 NOAA 公共对象存储的 GRIB 索引和 HTTP byte range 只下载所需字段（69 个状态字段约 54 MB/帧，另取少量真实降水字段），不下载完整全球 GRIB 文件。优先使用已发布的分析场；分析未发布时使用有效时刻相同的短时背景场，并记录每帧来源周期与提前量。相同起报时次使用缓存，较新的分析场发布后会升级背景场；自动缓存仅保留最近 48 小时。本项目的 ERA5 回测不能直接当作 GFS 起报后的实时精度验证。

## 后续核验与扩展

1. 核验具体机型手册、续航、起降工况和实际飞行速度定义。
2. 接入并核验权威空域/任务审批、三维建筑、线缆、树木和现场起降条件。
