# FuXi 本地点预报订正系统实施方案

> **执行路线更新（2026-09-17）**：本文是最初的 FuXi-2.1 方案，以下2.1相关步骤目前不作为实施依据。实际试验已改用 FuXi-1.0 的 `FuXi_EC` ONNX 模型：2026-01-15 的70通道输入和 `short` +6小时回报已跑通。当前进度与下一步以 [README.md](README.md) 为准；仍坚持冻结FuXi、另训小型订正模型的总体目标。

## 1. 项目目标

在不改动 FuXi-2.1 模型参数的前提下，构建一个本地点天气预报订正系统：

- FuXi-2.1 负责产生基础预报；
- 程序从全球预报中提取北纬 31.5°、东经 119.5° 的数据；
- 小模型学习“FuXi预报值与ERA5观测值之间的偏差”；
- 最终同时展示 FuXi 原始预报、订正后预报和改进幅度。

第一版优先服务低空应用，重点关注：

- 10米、100米风速和风向；
- 阵风；
- 2米气温、露点；
- 云量、云底高度；
- 边界层高度；
- 降水。

## 2. 明确不做的事情

- 不修改 `fuxi-2.1.pt2`；
- 不对 FuXi 内部参数做 LoRA 或全量微调；
- 不把单点 ERA5 数据伪装成 FuXi 的全球85通道输入；
- 不用0填充 `sst` 和 `cbh` 缺失值；
- 不使用未来观测作为预测特征，防止数据泄漏；
- 在没有历史配对样本前，不训练或发布虚假的“订正模型”。

## 3. 当前已有资源及结论

### 3.1 FuXi-2.1

- 模型：`D:\低空经济\fuxi-2.1\fuxi-2.1.pt2`
- 输入：两个相隔6小时的全球气象场；形状为 `(2, 85, 721, 1440)`
- 输出：每6小时一个全球预报场；最长40步，即10天
- 输出单位已经反归一化为物理单位
- 模型必须在 CUDA GPU 上运行，官方说明最低约8 GB显存

### 3.2 本地 ERA5 文件

- 类型：单点逐小时时间序列，不是全球网格
- 坐标：31.5°N、119.5°E
- 时间：2025-01-01至2026-09-10
- 记录数：14,832
- 变量数：20
- `sst` 全部缺失：该点为陆地，训练时排除
- `cbh` 缺失3,200条：保留缺失标记，不能填0

### 3.3 当前最大缺口

FuXi 示例输入对应 2024-09-29，而本地 ERA5 从 2025-01-01 开始。两者无法形成监督训练对。

订正训练必须具有以下同时间配对：

```text
FuXi在有效时间T的预测  →  ERA5在有效时间T的观测
```

所以在训练小模型之前，必须先补齐2025年以后的历史FuXi预报，或者从现在开始持续收集“预报—观测”样本。

## 5. 分阶段实施顺序

### 阶段0：环境和文件体检

先做：

1. 检查 NVIDIA GPU、显存、驱动和 CUDA；
2. 检查 `fuxi` Conda 环境中的 PyTorch、Xarray、NetCDF4；
3. 检查 `fuxi-2.1.pt2`、`mean.nc`、`std.nc`、`input.nc` 是否完整；
4. 读取示例输入的85通道、经纬度、时间和数值范围；
5. 建立配置文件，路径不硬编码到业务代码中。

验收标准：

- 程序能输出明确的环境检查结果；
- GPU不满足要求时直接停止并说明原因；
- 不进入训练阶段。

### 阶段1：跑通一次 FuXi 示例预测

先只预测一步，即 `+6h`：

1. 使用官方 `input.nc`；
2. 调用官方 `inference.py`；
3. 输出 `001.nc`；
4. 校验输出具有85个通道和 `721 × 1440` 网格；
5. 检查有效时间、NaN、无穷值及主要变量范围。

验收标准：

- FuXi原始目录没有任何变化；
- 应用自己的输出目录中生成有效的 `001.nc`；
- 能读取 `t2m`、`msl`、风和降水等通道。

说明：这一步只是冒烟测试，因为2024年的示例预报不能匹配2025年以后的观测。

### 阶段2：实现目标点抽取

1. 从每个 FuXi 输出文件中选择离 `(31.5, 119.5)` 最近的网格点；
2. 保存初始化时间、有效时间和预报提前量；
3. 映射变量名称：
   - FuXi `u10m/v10m` 对应 ERA5 `u10/v10`；
   - FuXi `u100m/v100m` 对应 ERA5 `u100/v100`；
   - 共同变量包括 `t2m`、`d2m`、`msl`、`tcc`、`tp`、`ssrd`、`fdir`；
4. 计算10米和100米风速：

```text
wind_speed = sqrt(u² + v²)
```

5. 点位结果保存为 Parquet 或 CSV；全球输出可以按保留策略归档或删除。

验收标准：

- 抽取结果只有目标点数据；
- 每行都有 `init_time`、`valid_time`、`lead_hours`；
- 数值与原始 NetCDF 对应网格点一致。

### 阶段3：获得历史 FuXi 预报

这是训练前的硬性门槛，有两条路线。

#### 路线A：历史回报实验（推荐）

1. 下载2025年以后的全球 ERA5/FuXi 所需85通道数据；
2. 每次准备两个相隔6小时的全球初始场；
3. 选择固定初始化频率，例如每天00 UTC；
4. 对每个初始化时刻运行 FuXi；
5. 立即抽取目标点；
6. 仅长期保存点位结果，减少磁盘占用。

优点：可以较快形成历史训练集。缺点：全球初始场数据量和计算量很大。

#### 路线B：从现在开始在线积累

1. 每天运行 FuXi 业务预报；
2. 保存点位预报；
3. ERA5更新后补录对应观测；
4. 积累数周至数月后再训练。

优点：无需大规模历史回报。缺点：需要等待，且早期样本不足。

阶段3验收标准：

- 至少有多个季节的数据；
- 每条样本的 FuXi `valid_time` 与 ERA5 时间严格一致；
- 包含多个预报提前量，而不是只有一个时刻；
- 记录生成来源、模型版本和初始化时间。

### 阶段4：构造订正训练集

每一行代表一个“地点—有效时间—提前量”样本。

建议输入特征：

- FuXi原始预报变量；
- `lead_hours`；
- 小时的正余弦编码；
- 年内日序的正余弦编码；
- 可选的近期实况，但只能使用预测发起时已经可获得的数据；
- 风速、温露差等派生变量。

监督标签：同一 `valid_time` 的 ERA5 观测。

订正目标分两类：

1. FuXi直接输出的变量：学习残差 `观测 - FuXi`；
2. FuXi没有直接输出的变量，如 `fg10`、`cbh`、`blh`：使用 FuXi 的相关变量预测其观测值。

缺失值处理：

- `sst`：从陆地点任务中排除；
- `cbh`：标签缺失时不参与该目标的损失/训练；
- 额外保留 `cbh_available` 标志，区分有有效云底记录和无记录。

防止数据泄漏：

- 严格按时间切分；
- 较早数据训练，中间数据验证，最新数据测试；
- 同一次预报初始化产生的所有提前量必须放在同一个集合；
- 标准化参数只能由训练集计算。

### 阶段5：训练小型订正模型

第一版不使用深度网络，优先使用稳定、易解释、CPU可训练的树模型：

- 每个目标变量训练一个 `HistGradientBoostingRegressor`；
- `lead_hours` 作为输入特征；
- 使用 `joblib` 保存模型、特征顺序和训练元数据；
- 设置随机种子，保证可复现。

选择该模型的原因：

- 数据量远小于全球天气模型；
- 能学习非线性偏差；
- 对特征缩放不敏感；
- 训练和推理成本低；
- 适合作为第一版基线。

只有当树模型在独立测试集上证明不足时，才考虑 MLP、LSTM 或更复杂的时序模型。

### 阶段6：评估是否真正改进

必须同时比较：

```text
基线A：FuXi原始预报
基线B：简单历史偏差订正
候选：小模型订正预报
```

连续变量指标：

- MAE；
- RMSE；
- 平均偏差 Bias；
- 不同 `lead_hours` 分组指标。

低空重点事件指标：

- 大风/阵风阈值命中率和误报率；
- 低云底事件命中率；
- 降水事件命中率；
- 高温、低能见度相关代理指标（若数据支持）。

上线门槛：订正模型必须在未参与训练的最新时间段上优于 FuXi 原始预报；若某变量变差，则该变量回退到 FuXi 原始值。

### 阶段7：形成统一预测流程

最终命令行流程：

```text
检查输入
  → 运行FuXi
  → 抽取目标点
  → 加载订正模型
  → 生成原始/订正对比
  → 导出CSV、Excel和图表
```

每次运行保存：

- FuXi版本；
- 订正模型版本；
- 初始化时间和有效时间；
- 原始值、订正值；
- 数据质量警告；
- 日志和运行耗时。

### 阶段8：再开发可视化界面

命令行流程稳定后，再增加轻量界面。界面只负责选择输入、启动任务和查看结果，不在界面代码中实现训练逻辑。

建议页面：

1. 环境检查；
2. FuXi基础预测；
3. 历史样本配对状态；
4. 训练订正模型；
5. 原始与订正结果对比；
6. 模型评估和版本记录。

## 7. 建议的执行批次

### 批次一：只验证，不训练

- 实现阶段0；
- 实现阶段1；
- 实现阶段2；
- 输出一次目标点的2024示例预测。

### 批次二：解决训练数据

- 决定历史回报或在线积累路线；
- 获取同时间 FuXi预报；
- 构造严格对齐的数据集；
- 输出配对率和缺失报告。

### 批次三：训练和评估

- 训练简单偏差基线；
- 训练小型树模型；
- 完成时间外测试；
- 只保留确实改进的目标变量。

### 批次四：业务化

- 统一预测命令；
- 日志、版本和异常处理；
- Excel/图表输出；
- 最后再开发界面。
